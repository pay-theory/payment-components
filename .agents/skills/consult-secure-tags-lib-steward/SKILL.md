# Consult the Secure Tags Library steward

Use when Payment Components work depends on hosted-field behavior owned by secure-tags-lib: iframe content, PostMessage messages, origin handling, field lifecycle, readiness, validation, tokenization coordination, or browser compatibility.

## Preconditions

Direct consultation requires an actually provisioned mailbox or consultation tool, exact contactable recipient identity, and sender/receiver policy allowing the exchange. Tool visibility alone is not authority.

If any condition is missing, prepare a principal-routed consultation packet and do not invent an address or send.

## Procedure

1. Ground in the local issue, authoritative local contracts, redacted evidence, and the precise hosted-field-owned unknown.
2. Confirm the question cannot be answered safely from local documentation and tests without guessing.
3. Remove payment data, production payloads, credentials, tokens, secrets, merchant identifiers, and unnecessary customer details.
4. Frame:
   - current local behavior or proposed contract change;
   - affected field, message, origin, readiness, or lifecycle identifiers;
   - redacted reproduction and evidence;
   - exact question or requested validation;
   - backward and forward compatibility impact;
   - rollout and rollback concern;
   - explicit statement that this steward will not edit secure-tags-lib.
5. Verify the consultation surface and authorization immediately before sending.
6. Send only through the provisioned route, or present the packet to the principal.
7. Treat the response as peer evidence, not permission to edit the peer, merge, publish, weaken security, or skip local validation.
8. Apply the answer only within confirmed local scope and record the durable non-sensitive contract decision.
9. Feed shared-contract conclusions into coordinate-payment-contract-change.

## Output

A sent consultation reference or principal-routed packet, followed by a bounded application note when a response arrives.

## Red flags

- Invented mailbox, recipient, or authority.
- Raw payment or production payload data.
- Asking the peer to approve local security weakening.
- Treating consultation as cross-repository write or release authority.
- Using peer silence as approval.
